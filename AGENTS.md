# Autominer Fix: notes for agents

A small Harmony mod that fixes the base game's Autominer (`Quarry`) leaving voxels untouched in
a vertical pit. [README.md](README.md) says what it does and how to build it. The diagnosis,
with the numbers behind it, is in the README's "What was wrong" section; read it before
touching the patches.

## Commit trailers

Every commit an agent makes ends with one trailer:

```
Assisted-by: AGENT_NAME:MODEL_VERSION [TOOL1] [TOOL2]
```

- `AGENT_NAME` is the agent, `MODEL_VERSION` the exact model that made the change, e.g.
  `Assisted-by: Claude:claude-sonnet-5-5`.
- The bracketed tools are optional: the square brackets in the format line mark them as
  optional and are not written. For example
  `Assisted-by: Claude:claude-sonnet-5-5 dotPeek UnityPy`. List only specialised analysis tools used for the change
  (for example a decompiler such as dotPeek, or UnityPy for reading prefab data), never
  everyday tools like git, dotnet or an editor.
- Never add `Co-Authored-By` or `Signed-off-by` lines. Those are for people.

## Working in this repo

- **Versioning.** The build runs `git describe --tags --match v*` (through
  `Template/create_version_info.py`), so it needs a commit and a `v*` tag. With no tag the
  version generator fails.
- **Stub DLLs.** `Main.props` removes `Template/libs/**` from the build's candidate assemblies.
  Keep that line: without it the build silently compiles against the template's stub game DLL
  (an older game version) instead of the real install.
- **Local paths.** The game's DLL folder and the install folder go in the gitignored
  `Local.Developer.props`. Local installs go to LaunchPad's mods folder
  (`%USERPROFILE%\Documents\My Games\Stationeers\mods\AutominerFix\`), never `BepInEx/plugins`.
  `dotnet build Main.csproj -t:Install` does the copy.
- **LaunchPad needs `About/thumb.png` and `About/Preview.png`.** They are generated by
  `python tools/make_images.py` (Pillow); edit the script, not the PNGs.
- **Private game members.** `Template/Template.props` publicizes `Assembly-CSharp`, so the
  patches name `Quarry`'s private fields and methods directly. The transpiler matches IL by
  shape and refuses to patch (with a warning in the BepInEx log) if the game's `RunDrillBit`
  no longer has the shape it expects. After a game update, check that warning first.
- **The decompiled source.** Decompile the game's `Assembly-CSharp.dll` (for example with
  dotPeek); `Quarry` is `Assets\Scripts\Objects\Electrical\Quarry.cs` in the output. Note that
  `HorizontalQuarry.cs` is the horizontal auto miner, a different machine.
- **CI.** `.github/workflows/deploy.yml` hands off to `Template/action.yml`, which builds
  against the template's stub DLLs and, on a `v*` tag, attaches a zip of the DLL and `About/`
  to a GitHub release.
